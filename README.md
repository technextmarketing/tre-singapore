# TRE™ in Singapore — website

A static, dependency-free HTML/CSS/JS website for **TRE™ in Singapore** (tre-in-singapore.com), built as a community hub for TRE™ (Tension & Trauma Releasing Exercises) practitioners in Singapore.

## Pages

| File | Purpose |
|------|---------|
| `index.html` | Home — hero, pillars, what is TRE™, practitioner hub, upcoming events, founder spotlight, blog teasers |
| `about.html` | Who we are, Isabelle's biography and milestones, values, the operating company |
| `education.html` | What TRE™ is, how it works, safety, who it is for, the 3-module certification, fees table, FAQ |
| `facilitators.html` | One filterable, searchable grid of every trainer and provider (order shuffles on each load; data in `assets/js/facilitators-data.js`), "get listed" |
| `facilitators/<id>.html` | Facilitator profile (public URL `/facilitators/<id>`, generated by the build): hero with portrait, services ticker, credentials, offers, gallery with lightbox, upcoming events, contact/socials |
| `events.html` | Events & Sessions (mirrors hummingbeing.com/events.html): countdown, timeline, filter tabs, event cards, past events, online prep summary |
| `events/<slug>.html` | Event page (public URL `/events/<slug>`, generated by the build from `assets/js/events-data.js`) |
| `event.html?id=…`, `facilitator.html?id=…` | Templates for records added since the last build; known ids forward to their own pages |
| `online-session-guide.html` | Our own guide to setting up for an online TRE™ session (camera diagrams, checklist, safety, Zoom, on-the-day, FAQ) |
| `blog.html` | Article listing + newsletter box |
| `blog/*.html` | Six full articles |
| `contact.html` | Contact details, form, map, response times, FAQ |

Shared assets: `assets/css/style.css` (design system, self-hosted fonts at the top) + `assets/css/layer.css` (heroes, motion, shared blocks), `assets/js/main.js` (site behaviour, event/facilitator rendering, forms, TRE™ explainer bubble, lobby ambience), `assets/js/layer.js` (tremor lines, drawn lines, lightbox, the pause control), `assets/js/chatbot.js` (rule-based site assistant, no external calls), `detail.css/js` (event and facilitator pages), `article.css/js` (articles), `assets/js/events-data.js`, `assets/js/facilitators-data.js`, `assets/fonts/` (Plus Jakarta Sans + Inter, SIL OFL), `assets/img/`, `assets/video/`.

Site-wide behaviours: every "TRE™" in page text becomes a tappable term that opens a bubble explaining the name and origin; a soft generative ambient pad plays at 10% volume after the visitor's first tap (toggle bottom-right, remembered in localStorage); the floating cluster is back-to-top + WhatsApp on the bottom row with sound and "Ask us" chat above. The home hero shows its still photo first and then plays a muted loop (`assets/video/hero-loop.*`, and `hero-loop-960.*` on phones — replace both cuts to change it). Every hero and ribbon has a pause button: one site-wide switch, remembered per visitor, that stops the video, the slow photo drift, the gold lines and the ribbons (WCAG 2.2.2). With "reduce motion" switched on in the visitor's system, nothing moves in the first place.

## Pictures

Pictures referenced by the data files (event posters, facilitator photos and galleries) get smaller WebP copies (`<name>-<width>.webp`) from `_src/images.py`, and `main.js` serves the right size with `srcset`. The build makes the copies for newly added pictures when Pillow is installed (`pip install pillow`; the nightly GitHub job installs it), and only lists copies made from the current version of a picture. Every picture has a `.json` provenance sidecar.

## Editing the header, navigation or footer

The finished pages are plain HTML and can be edited directly. To change the header, navigation or footer on **every** page at once, edit `_src/parts/head.html` or `_src/parts/footer.html` (page bodies are in `_src/parts/*.body.html`) and run:

```bash
python _src/build.py
```

This regenerates all pages. The `_src` folder is not needed on the web server.

## Editing events

All events live in **`assets/js/events-data.js`** — one object per event, documented at the top of the file. Each event gets its own page at **`/events/<slug>`** (generated by `python _src/build.py`; until the next build a new event still works through `event?id=<slug>`).

The listings mirror **hummingbeing.com/events.html** and its event pages. Each event has a `slug`, a 16:9 `image` in `assets/img/events/` (the same posters used on hummingbeing.com) and a `details` block with the programme, pricing tiers, facilitators, registration links and, for online events, the preparation guide.

**Events keep themselves current.** Event times are the clock at the event's own place — Singapore by default, `tz: 'Europe/Bucharest'` for Bucharest venues (detected automatically) — so every visitor, in any time zone, sees the same moment. Once an event's last day has ended there, it moves to "Past events" on its own: on the events page, the home page, the chatbot, its event page (registration closes) and the facilitator pages. The countdown skips postponed and cancelled events and moves on to the next event the moment one starts. Mark a postponed or cancelled event with `status: 'postponed'` / `status: 'cancelled'` — it is labelled on the site, flagged for Google and never counted down to.

## Event blog posts (preview + recap)

Every event gets a **preview** post, and a **recap** post after it ends. Posts are files in `_src/posts/<slug>.html` (a short JSON header, then optional HTML; with no HTML the text is generated from the event's data — see `_src/event_posts.py`).

- **Drafts** (`"status": "draft"`) are built at `/drafts/<slug>`: hidden from Google, not linked anywhere, not in the sitemap — a private link to review.
- **Published** posts (`"status": "published"`) appear at `/blog/<slug>`, on the blog page, on the event's page ("From the blog"), in the sitemap and in `llms.txt`.
- The nightly job drafts what is missing: a preview for each new event, a recap the day after an event ends (with a reminder to add photos and highlights), and opens a GitHub issue for each new draft. A person approves each one before it is published.

## How the site updates itself

`.github/workflows/pages.yml` runs on every push to `main` **and every night shortly after midnight Singapore time** (scheduled 00:23; GitHub can start scheduled runs late). It runs `python3 _src/build.py --auto-drafts` (the build reads the data files through headless Chrome, which the GitHub runner has), commits any changes back to `main`, deploys, and opens issues for new drafts. If the build fails, the committed pages are deployed unchanged. Because the job commits to `main`, **pull before you push**. GitHub pauses scheduled workflows after 60 days without any repository activity; the nightly commits normally keep it alive, and re-enabling it is one click under *Actions*.

## Forms

The contact form and the newsletter sign-up send through FormSubmit (`formsubmit.co/ajax/isabelle@bhdasia.com`) inside the page. FormSubmit asks the inbox owner to activate a form once per website address: until the activation email is confirmed, a message is **not** delivered — the page then says so and offers the visitor the same message as a ready-written email or WhatsApp, instead of a false "sent". After any domain change, send one test message and confirm the activation email in isabelle@bhdasia.com.

## Content that is written by hand

Most dates and prices come from `events-data.js` and update themselves. These do not and need a look when a new certification cohort is announced: the Education page's module dates and fee table (`_src/parts/education.body.html`), the certification and price answers in `assets/js/chatbot.js`, and the cohort sentences in the "TRE™ for coaches" and "From provider to certifying trainer" articles.

## Deploying

The site is hosted on GitHub Pages at **https://tre-in-singapore.com** (GoDaddy DNS points the domain at GitHub; HTTPS is enforced). Pushing to `main` deploys it through `.github/workflows/pages.yml`. Pages have clean URLs (`/about`, `/events/<slug>` — GitHub serves `about.html` for `/about`); to preview locally with the same behaviour, run `python ~/ClaudeWork/qa/clean_server.py 3971` from any folder, or any static server that maps `/x` to `x.html`.

## Design notes

Palette taken from the TRE Singapore logo: navy `#1c3d7a` (TRE wordmark), globe blue `#2a63a8`, bronze `#8b6b45` (continents/eagle), brown `#5f4630` ("Singapore"), plus the orange `#e08a2e` CTA colour and cream `#fbf5ec` panels used on the current site. Fonts match technext.asia: Plus Jakarta Sans (headings, italic accents echoing the logo) and Inter (body), self-hosted in `assets/fonts` (the two upright Latin files are preloaded) with metric-matched local fallbacks so text keeps its line breaks while they load (`~/ClaudeWork/qa/tre_fonts.py` regenerates the CSS).
